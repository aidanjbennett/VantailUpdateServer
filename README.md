# Vantail Update Server

## Local PostgreSQL

The application uses PostgreSQL through Spring Data JPA. To start the local database:

1. Copy `.env.example` to `.env` and change the password if needed.
2. Start PostgreSQL with `docker compose up -d database`.
3. Load the same settings into the application process and start it with `set -a; . ./.env; set +a; ./gradlew bootRun`.

The default JDBC URL is `jdbc:postgresql://localhost:5432/vantail_update_server`. Set
`DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` in the environment to connect to a different
database. The Compose service uses `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, and `DB_PORT`.

## Publish an update

Publish a signed update manifest with `POST /updates`:

```bash
curl -X POST http://localhost:8080/updates \
  -H "X-Update-Publish-Secret: $UPDATE_PUBLISH_SECRET" \
  -H 'Content-Type: application/json' \
  -d '{
    "version": "1.1.0",
    "notes": "Fixes the thing",
    "pubDate": "2026-08-22T09:00:00Z",
    "platforms": {
      "darwin-aarch64": {
        "url": "https://downloads.example.com/1.1.0/App-1.1.0-darwin-aarch64.tar.gz",
        "signature": "B5XlVy0pAcaNt/4GCPqqxQj/..."
      }
    }
  }'
```

Versions must be unique. The signature must be the real Ed25519 signature for the
archive bytes generated by the Vantail updater tooling.

The updater can use a platform-aware endpoint with placeholders:

```text
http://localhost:8080/update/latest/{{target}}/{{arch}}/{{currentVersion}}
```

For example, the client resolves that to
`/update/latest/darwin/aarch64/1.0.0`. The client remains responsible for comparing
the returned version with its current version using semantic-version rules.

## Docker

Build and run the application container with:

```bash
docker build -t vantail-update-server .
docker run --rm -p 8080:8080 \
  -e DB_URL=jdbc:postgresql://host.docker.internal:5432/vantail_update_server \
  -e DB_USERNAME=vantail_app \
  -e DB_PASSWORD=choose-a-strong-password \
  -e UPDATE_PUBLISH_SECRET=replace-with-a-long-random-secret \
  vantail-update-server
```

After tests pass, GitHub Actions publishes the image to GitHub Container Registry on
pushes to `main` and on version tags beginning with `v`. Pull requests run the tests
and build the image without publishing. Use the published image with:

```bash
docker pull ghcr.io/aidanjbennett/vantailupdateserver:latest
```
